# Fishing Log App プロジェクトルール

Version 1.0

最終更新：2026/08/01

---

# プロジェクトの目的

Fishing Log App は、

「釣れた瞬間を30秒で記録し、
あとから振り返ることが楽しくなるアプリ」

を目的とする。

釣り人自身が使いたくなることを最優先とする。

---

# このアプリが目指すこと

Fishing Log App は

「釣果を保存するアプリ」

ではなく

「また釣りに行きたくなるアプリ」

を目指す。

---

# MVP方針

最初から多機能を目指さない。

小さく完成させ、
実際に使いながら改善する。

---

# 開発優先順位

優先順位は以下とする。

1. 動作
2. 使いやすさ
3. デザイン
4. 拡張性

---

# デザイン方針

シンプルで見やすいUIを採用する。

装飾より情報を優先する。

暗い海でも見やすいダークテーマを基本とする。

---

# ログ保存

釣果ログは長期間保存できることを目的とする。

既存データとの互換性を可能な限り維持する。

旧データが存在しても正常に動作すること。

---

# 写真

写真は任意とする。

写真本体はIndexedDBへ保存する。

釣果データには写真IDのみ保持する。

---

# SNSカード

Fishing Log の特徴機能とする。

目的は

「SNSへ簡単に投稿できる釣果カード」

を作成することである。

基本デザインはClassic Themeを採用する。

4:5比率を基本とする。

表示項目はON/OFF切り替え可能とする。

---

# 表示項目

初期状態

・場所：表示

・潮情報：表示

・天気：表示

・釣り方：非表示

・メモ：表示

・日付：非表示

---

# パフォーマンス

軽快な動作を優先する。

不要なライブラリは追加しない。

ブラウザ標準機能を優先して利用する。

---

# 保守性

機能ごとにモジュールを分離する。

責務を明確にする。

将来の追加機能を考慮した構成とする。

---

# AI提案

改善案は歓迎する。

ただし、

仕様変更は社長承認後のみ実装する。
