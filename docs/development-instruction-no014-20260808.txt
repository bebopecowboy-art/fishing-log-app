AI事業部 開発指示書 No.014

提出日：2026/08/08

件名

Otomo Fishing
魚種入力標準化・履歴候補機能（Version 1）

────────────────────────────────────

【作業開始】

最初に以下のファイルを読み、内容を理解してから作業を開始してください。

docs/00-ai-development-rules.md
docs/01-fishing-log-project-rules.md

内容を理解したことを最初に報告してください。

共通ルール、プロジェクトルール、本指示書の内容に矛盾がある場合は、
実装を開始せず社長へ確認してください。

────────────────────────────────────

【背景】

今後、保存済み釣果の検索・絞り込み・集計・AI分析を行う予定です。

その前段階として、
魚種名の表記揺れを減らし、
ユーザー自身の釣果履歴から魚種候補が育つ仕組みを実装します。

全国共通の魚種辞書は今回作成しません。

地域名・地方名・釣り人ごとの呼称を尊重し、
ユーザーが普段使用する魚種名を、
そのユーザー自身のOtomo Fishing内で統一して使えることを優先します。

────────────────────────────────────

【今回の目的】

以下を実現してください。

1.
魚種入力を保存時にカタカナ表記へ正規化する。

2.
過去に保存した魚種を、
次回以降の魚種入力候補として表示する。

3.
候補に存在しない魚種も自由に新規入力できる。

4.
同一魚種の表記揺れ・重複を減らし、
将来の検索・集計に使いやすいデータを蓄積する。

────────────────────────────────────

【基本方針】

・魚種はユーザー自身の履歴から候補を育てる。
・初期状態で大量の魚種マスタは持たせない。
・地方名、通称を別の正式名称へ強制変換しない。
・「アコウ」を「キジハタ」へ自動変換しない。
・「チヌ」を「クロダイ」へ自動変換しない。
・ユーザーが入力した呼称を尊重する。
・ただし保存形式はカタカナへ統一する。
・既存ログは今回一括変換しない。
・既存ログを破壊しない。

────────────────────────────────────

【魚種入力の正規化仕様】

保存時および候補照合時に、
魚種入力へ以下の正規化を行ってください。

1.
前後の空白を削除する。

2.
ひらがなは対応する全角カタカナへ変換する。

例：

あじ
→
アジ

あこう
→
アコウ

3.
半角カタカナは全角カタカナへ変換する。

例：

ｱｼﾞ
→
アジ

4.
正規化後の値を、
保存する魚種名として使用する。

5.
同一魚種候補の重複判定も、
正規化後の値で行う。

────────────────────────────────────

【許可する文字】

Version 1では、
魚種名として以下を許可してください。

・全角カタカナ
・長音記号「ー」
・中点「・」

必要に応じて、
一般的な魚種名として自然に使用される記号が既存データ上必要である場合は、
実装前に社長へ確認してください。

────────────────────────────────────

【許可しない文字】

以下が正規化後の魚種名に含まれる場合は、
保存せずユーザーへ案内してください。

・漢字
・ひらがな
　※ひらがなは正規化処理後に残っている場合のみエラー
・英字
・数字
・絵文字
・魚種名に不要な記号

エラー例：

「魚種はカタカナで入力してください。」

または、

「魚種名にはカタカナ・ー・中点のみ使用できます。」

ユーザーが何を直せばよいか分かる文言にしてください。

────────────────────────────────────

【既存ログの扱い】

既存ログは今回一括変換しないでください。

既存ログに、

・漢字魚種
・ひらがな魚種
・半角カタカナ魚種
・その他の旧形式

が存在しても、
ログ本体はそのまま維持してください。

ただし、
候補一覧を生成する際は、
安全に正規化できる既存魚種については、
正規化した候補として利用して構いません。

例：

既存ログ「あじ」
→ 候補「アジ」

既存ログ「ｱｼﾞ」
→ 候補「アジ」

既存ログ「鯵」
→ 自動で「アジ」へ推測変換しない。
→ 候補へ追加しない、または既存値としてのみ扱う。

漢字から魚種名を推測する辞書機能は今回実装しないでください。

────────────────────────────────────

【魚種候補の生成】

魚種候補は、
保存済み釣果ログの魚種履歴から生成してください。

候補専用の魚種マスタを別途手入力で作る必要はありません。

候補生成時は、

・空欄を除外
・正規化可能な値を正規化
・同一魚種を重複表示しない

こと。

候補の保存方法は、
既存ログから都度生成する方式、
または安全な派生データとして保持する方式のうち、
既存設計に適した方法を採用して構いません。

ただし、
魚種候補だけを理由に既存ログ構造を大きく変更しないでください。

────────────────────────────────────

【候補表示】

魚種入力欄を操作した際に、
過去に保存した魚種候補を表示してください。

以下を満たしてください。

・候補をタップ／クリックすると魚種欄へ入力できる。
・入力文字に応じて候補を絞り込む。
・ひらがな入力中でも、カタカナへ正規化したうえで候補照合する。
・半角カタカナ入力中でも、全角カタカナへ正規化したうえで候補照合する。
・候補にない魚種もそのまま新規入力できる。
・候補選択を必須にはしない。

例：

履歴候補：

アジ
アコウ
アオリイカ

入力：

あ

候補：

アジ
アコウ
アオリイカ

入力：

あこ

候補：

アコウ

────────────────────────────────────

【候補の並び順】

Version 1では、
ユーザーが使いやすいよう、
最近使用した魚種を優先してください。

同一魚種を複数回保存していても、
候補には1件だけ表示してください。

最近使用した順の判定が既存ログ構造上困難な場合は、
既存ログの新しい順を利用してください。

────────────────────────────────────

【新規保存時】

新しい魚種を入力して正常保存した場合、
次回以降その魚種が候補へ表示されるようにしてください。

例：

これまでの候補：

アジ
アコウ

新規入力：

ヒラメ

保存成功後の候補：

ヒラメ
アジ
アコウ

候補表示のためだけに、
別途ユーザー操作を必要としないこと。

────────────────────────────────────

【編集時】

保存済みログを編集する場合も、
同じ魚種正規化ルールを適用してください。

編集時にも魚種候補を利用できるようにしてください。

編集前の魚種を変更しなかった場合、
不要な変換やデータ破壊を起こさないよう注意してください。

既存ログに旧形式の魚種名が存在し、
編集で魚種欄を変更した場合は、
変更後の値に今回の正規化ルールを適用してください。

────────────────────────────────────

【空欄の扱い】

現在の既存仕様で魚種が必須の場合は、
その仕様を維持してください。

既存仕様で魚種空欄が許可されている場合も、
今回の指示だけを理由に必須化しないでください。

既存の必須／任意仕様を変更しないこと。

────────────────────────────────────

【UI】

既存デザインを大きく変更しないでください。

候補UIは、
スマートフォンでタップしやすく、
入力欄の操作を邪魔しないものにしてください。

候補が存在しない場合は、
候補欄を無理に表示しなくて構いません。

候補が多い場合でも、
画面を大きく占有しすぎないようにしてください。

────────────────────────────────────

【今回実装しないもの】

以下は今回の対象外です。

・全国魚種マスタ
・魚種図鑑
・学名
・英名
・地方名辞書
・漢字魚名辞書
・魚種の自動推測
・「アコウ」と「キジハタ」の内部統合
・類義語統合
・魚種別検索
・フリーワード検索
・複数条件検索
・統計機能
・AI分析
・場所入力の標準化
・釣り方入力の標準化
・既存ログの一括データ移行
・ブランドUI変更

────────────────────────────────────

【エラー時の安全性】

入力正規化や候補生成に失敗しても、
既存ログを破壊しないでください。

候補表示機能のエラーによって、
通常の魚種入力・釣果保存・編集機能が使用不能にならないようにしてください。

保存時の入力エラーは、
ユーザーが修正できる形で表示してください。

────────────────────────────────────

【AIの裁量】

以下は既存コードを確認したうえで、
最小限の変更で最適な方式を採用して構いません。

・正規化処理を置くモジュール
・候補生成ロジックの配置
・候補UIの具体的な表示方式
・候補の最大表示件数
・候補表示／非表示のタイミング

ただし、
魚種名の意味をAI側で推測して別名称へ変換しないでください。

本指示書に不要な大規模リファクタリングは行わないでください。

────────────────────────────────────

【テスト】

以下を実施してください。

・「アジ」の保存
・「あじ」→「アジ」への変換
・「ｱｼﾞ」→「アジ」への変換
・前後空白の削除
・長音記号を含む魚種名
・中点を含む魚種名
・漢字を含む魚種名の拒否
・英字を含む魚種名の拒否
・数字を含む魚種名の拒否
・絵文字を含む魚種名の拒否
・魚種候補生成
・候補重複除外
・最近使用した魚種の優先
・候補タップ／クリック入力
・ひらがな入力による候補絞り込み
・半角カタカナ入力による候補絞り込み
・候補にない新規魚種の入力
・新規魚種保存後の候補追加
・編集画面での候補表示
・編集時の魚種正規化
・旧ログ「あじ」から候補「アジ」を生成
・旧ログ「ｱｼﾞ」から候補「アジ」を生成
・旧ログ「鯵」を勝手に「アジ」へ変換しない

実ブラウザで確認できない項目は、
未確認事項として明確に報告してください。

────────────────────────────────────

【完了条件】

以下をすべて満たした時点で本作業は完了とします。

・ひらがな魚種をカタカナへ自動変換できる。
・半角カタカナ魚種を全角カタカナへ自動変換できる。
・前後空白を除去できる。
・正規化後の魚種名を保存できる。
・許可外文字を含む入力を適切に拒否できる。
・過去の魚種履歴から候補を生成できる。
・同一候補が重複表示されない。
・入力文字に応じて候補を絞り込める。
・候補にない新規魚種も登録できる。
・新規保存した魚種が次回候補になる。
・編集時にも同じ正規化・候補機能を利用できる。
・既存ログを一括変更しない。
・漢字魚種を推測変換しない。
・既存の釣果保存・編集機能を壊していない。
・既存テストを含む自動テストが成功する。
・UTF-8形式の開発完了報告書をdocsフォルダへ保存している。
