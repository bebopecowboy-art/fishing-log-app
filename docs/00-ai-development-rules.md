# AI事業部 開発共通ルール

Version 1.0

最終更新：2026/07/31

目的

本ルールは、AI事業部で行うすべての開発に共通して適用する。

対象

・開発担当AI
・レビュー担当AI
・今後追加されるAI社員

────────────────────

【基本方針】

1.
社長の指示を最優先とする。

2.
不明点は推測で実装せず、必ず質問して確認する。

3.
完成度よりも、動作する小さな機能を優先する。

4.
一度に大きな変更を行わず、1つの機能ごとに実装する。

────────────────────

【開発フロー】

基本フローは以下とする。

1.
共通ルールを読む

2.
プロジェクトルールを読む

3.
今回の開発指示書を読む

4.
不明点を質問する

5.
実装

6.
テスト

7.
開発完了報告書を作成

8.
社長の承認待ちで停止

────────────────────

【実装ルール】

・変更範囲は開発指示書に従う。

・不要なリファクタリングは行わない。

・既存機能を壊さないことを優先する。

・保守性を意識した実装を行う。

────────────────────

[作業開始時]

・共通ルール
・プロジェクトルール
・今回の指示書

を読んだことを最初に報告する。

────────────────────


【テスト】

開発完了時は可能な限りテストを実施する。

・自動テスト
・構文チェック
・動作確認
・必要な検証

────────────────────

【報告書】

開発完了時はUTF-8のテキスト形式で報告書を作成する。

報告書は
docs/
へ保存すること。

報告書には以下を含める。

・変更内容
・追加ファイル
・変更ファイル
・実施したテスト
・テスト結果
・未確認事項
・残るリスク
・次工程への提案

────────────────────

【証拠】

テスト結果など、社長が確認できる情報を可能な範囲で添付する。

────────────────────

【Git】

社長の承認があるまで

・コミット
・プッシュ
・公開

を行わない。

────────────────────

【文字コード】

作成するテキストファイルは
UTF-8で保存すること。

────────────────────

【Codex利用状況・作業評価】

作業終了時は、可能な場合、Codexの利用状況を確認して報告する。

可能であれば /status 等の利用状況確認機能を使用すること。

取得できない場合は
「取得不可」
と記載する。

また、毎回以下を自己評価として報告すること。

【作業規模】

・小
・中
・大

の3段階で評価する。

【作業難易度】

・低
・中
・高

の3段階で評価する。

評価理由として、以下を簡潔に記載する。

・変更ファイル数
・追加ファイル数
・主な実装内容
・実施したテスト数
・特に難しかった点
・特に簡単だった点

これらは今後のAI事業部の開発データとして蓄積する。
────────────────────

【改善提案】

開発中に改善案が見つかった場合は、

実装せず、

報告書へ提案として記載する。

────────────────────
【AIの裁量】

AIは開発品質向上のための提案を行ってよい。

ただし、

仕様変更は行わない。

仕様変更が必要と判断した場合は、
社長へ提案し、承認を得てから実装する。

────────────────────

本ルールはAI事業部全プロジェクトへ適用する。
